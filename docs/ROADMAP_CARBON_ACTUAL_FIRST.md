# Carbon Actual First Roadmap

## Phase 0 — Boundary freeze

- Adopt Carbon Actual Core / Tenant / Domain Node / Student Experience boundaries.
- Keep NOUN data institution-controlled.
- Keep ABBA master intelligence in Carbon Actual Core.
- Keep Vercel as serverless backend + viewing portal; Supabase as system of record.

## Phase 1 — Platform foundations

1. tenant_id on tenant-scoped tables
2. tenant-aware RLS
3. identity and role model
4. audit events
5. consent/preferences model
6. secret/environment separation
7. backup/restore verification
8. rate limiting and webhook verification

## Phase 2 — NOUN domain completeness

1. complete programme/faculty/department/course graph
2. source registry and health
3. academic calendar/exams/TMA intelligence
4. verified human contacts
5. student 360
6. opportunities
7. services/provider intelligence
8. WhatsApp communication engine

## Phase 3 — ABBA intelligence

1. retrieval/embeddings when justified by content volume
2. source freshness and authority scoring
3. evidence trails
4. insights
5. recommendations
6. demand/supply intelligence
7. AI observability
8. human escalation learning loop

## Phase 4 — Carbon Actual commercial platform

1. Carbon Actual control plane
2. tenant provisioning
3. institutional onboarding
4. pricing and billing
5. provider onboarding
6. marketplace workflows
7. campaign governance
8. platform analytics

## Phase 5 — Replication

- package NOUN deployment as the reference tenant
- deploy a second institution without forking core
- prove tenant isolation
- compare operating cost and retention
- establish repeatable sales/onboarding playbook

## Non-negotiable rule

Do not optimize for handing a bespoke NOUN bot to one institution. Optimize for a reusable Carbon Actual platform whose first production tenant is NOUN, while preserving a contractual path for dedicated/private deployments and enterprise handoff.
